# Pull 5: games of Contagion, Complacency and the top rivals (2026-11-08)

Pull 5 adds 72 replays to the validation set of the simulator. It was collected on 2026-11-08 through a logged-in browser session, one request at a time.

## What was pulled

| Item | Count | File |
|---|---|---|
| Match-list pages (ladder, newest first) | 12 pages, 480 finished matches, ids 105881 to 106358 | `data/pull5/matchlist-105881-106358.json` |
| Leaderboard | 1 snapshot | `data/pull5/leaderboard-2026-11-08.json` |
| Match pages | 72 (one for each chosen game) | `data/pull5/matches-pull5-2026-11-08.json` |
| Replays | 72 (ids 105881 to 106357), 1.6 GB gzipped (2 to 62 MB each) | `data/pull5/replays/` (git-ignored) |

The project now has 148 replays in total (76 from pulls 1 to 4, 72 from pull 5). The limit is 150.

**Pacing.** List and match pages were read 2 seconds apart, and replays at least 4 seconds apart. No request ran in parallel. The site gave no HTTP 429 response and no other error. Every replay was available. Current pacing (2026-11-08): see "Pacing rules for the site" in `architecture/data-pulls.md`.

**How the replays were saved.** The page fetched `/api/matches/<id>/replay`. The browser removed the gzip transfer encoding, so the bytes started with `CHR2` (62 MB for match 105881). The page compressed them again with `CompressionStream('gzip')` and saved them as `<id>.chr2.gz` through a download link. Then the files were moved from the download folder into `data/pull5/replays/`.

**Match pages.** The first read of the match pages lost the rating column, because the table has an empty first cell (the colour swatch). The pages were read again with the last nine cells of each row. Only the second read is stored.

## Selection

All 72 games are finished ladder games from the 480 newest. The aim was to give the simulator more examples for the rival models and for our two ladder cells.

- **Our cells.** Contagion in 18 games (10 wins, 8 losses). Complacency in 18 games (11 wins, 7 losses). Two games have both cells (106052, 106276). Losses are over-sampled on purpose: in the 480-game list, Contagion won 77% and Complacency 81%.
- **Rival games.** 38 games without our cells, chosen so that each top rival appears in at least 8 new replays.
- **Models.** 68 games have only cells with a simulator model: the nine top rivals (model), our cells and the house cells Hunter, Medic, Walker and Random (exact). Four Complacency losses have one cell with only a rough stand-in (106225 Bulwark, 106281 squirtle, 106292 gemAlert_v3, 106303 choochoo). They were added because only 2 Complacency losses had no rough cell.

## Validation sets

`sim/validate.py` now reads pull 5 (`PULLS`), and the cell Complacency has its exact model. The pool has 135 matches.

The FIT and TEST sets are now fixed in `data/splits/split.json`. A match keeps its set after it is assigned, because the simulator was tuned on the FIT set. Re-running the old rule over all 135 ids would have moved 27 of the 63 older matches (14 from FIT to TEST). So:

- Pulls 2 to 4 keep their sets: FIT 42, TEST 21 (pull 2: 24/12, pull 3: 10/5, pull 4: 8/4). This is the same assignment as before.
- Pull 5 was split alone with the same rule (shuffle with seed 20261108, sort by real winner and pull, every third match is TEST): FIT 48, TEST 24.
- Total: FIT 90, TEST 45.

`python validate.py --extend-split` gives a set to new matches only. It does not change the sets that exist.

Smoke test: `python validate.py --matches 106351 --workers 1` found the match and ran it (79 s, same winner as the real game). No tuning and no full validation run was done.

- The four games with a rough stand-in count as "rough" in the validation report.
